QUESTIONS & ANSWERS

Working with
OncoloHealth.

What does OncoloHealth bring together?+

The project connects cancer datasets, specialist models, data review, and evaluation in a research workbench.

Can every cataloged model be used commercially?+

No. Dataset and model licenses, access conditions, and inference permissions differ. Each must be reviewed for the intended use.

What would a collaboration look like?+

That depends on the question. Relevant starting points include dataset evidence, reproducible workflows, evaluation design, and research partnerships. Connect with Jordi on LinkedIn to start a conversation.

HOW TO CONTRIBUTE

Claim a workstream.
Keep the record.

These steps follow the project’s working rules in PROGRESS.md and AGENTS.md. Datasets and models also need the documentation set out in the contribution standard.

Read the contribution standard ↗
  1. 01

    Read the map

    Start with ARCHITECTURE.md for the code, PROGRESS.md for status and owners, and the research context for the scientific ground rules.

  2. 02

    Claim a workstream

    Put your name in the owner cell of one workstream in PROGRESS.md, from dataset curation (A) to independent review (H).

  3. 03

    Stay inside your modules

    Treat other modules as fixed interfaces. If you need a change there, open an issue or pull request and tag its owner. Shared types and the manifest contract need review from two workstreams.

  4. 04

    Test with synthetic fixtures

    Mark fixtures SYNTHETIC and never report synthetic results as medical performance. Run python3 -m unittest discover -s tests before pushing; the core stays standard-library only.

  5. 05

    Report what you found

    Put deliverables in docs/reports/<workstream>-<topic>.md. Evidence states change only through a reviewed pull request to the catalog.

QUESTIONS & ANSWERS

Before you
ask.

Short answers drawn from the repository and the sharing standard.

Which licence covers the code?+

A licence for the project code has not been chosen yet; it is an open decision in the progress record. Datasets and models keep their own licences and access terms, recorded in each catalog record.

Where do I report a problem?+

Open a GitHub issue. For a catalog correction, name the record id and the source that supports the change. Evidence states change only through a reviewed pull request.

Can I contribute a dataset or model?+

Not through this website, which does not accept uploads. The contribution workflow and its safeguards are planned for the next release. Model weights alone cannot establish that their training data were free of private information.

What do I need to run the workbench?+

Python 3.11 or later for the core, which uses only the standard library. Model work and live scoring need the pinned ml extra. The default download tier is about 5.3 GB, within a 40 GB storage budget you can change.

Where does the app run?+

On your machine. The researcher app binds to 127.0.0.1 and checks the host and a per-launch token. Downloads come from each record’s publisher, and the assistant connects to the endpoint profile you configure.

Can every cataloged model be used commercially?+

No. Dataset and model licences, access conditions, and inference permissions differ. Each must be reviewed for the intended use.

CONTRIBUTION REVIEW / NEXT RELEASE

What a contribution
must document.

Sharing a useful resource requires a clear record of where it came from, what it contains, and how it may be used.

The next release is planned to include safeguards for contribution review and sharing. Unverified sources, permissions, or training-data documentation should keep a contribution from being released.

Source & version
Where the resource originated, the release or checkpoint, and the records needed to trace it.
Permissions
The dataset and model terms, authorized uses, and any restrictions on redistribution.
Private-information review
Evidence of the review of data for private personal information, including patient identifiers and sensitive personal details.
Training provenance
For models, the datasets and methods used in training. Submitting weights alone does not establish the privacy of the training data.
Release context
The intended use, method, and known limitations that must accompany an eligible contribution.

THE PROJECT

Keep the source.
Build on the result.

A useful result needs a record of the data, model, permissions, and choices behind it.

OncoloHealth brings those records into the research workflow. Our work includes dataset and model catalogs, local specialist demonstrations, and exploratory studies of data quality and model performance.

The BTXRD audit is one example: duplicate images and label conflicts led to a closer review of the release and the limits of its published splits.
